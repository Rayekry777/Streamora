# Streamora 部署与结果汇报

GitHub 负责独立功能验证、阶段验收、部署、浏览器 E2E、回滚和脱敏诊断。它不调用模型、不创建修复 PR，也不自动合并或部署。

## 阶段流程

1. 在 IDEA 完成当前服务的开发与调试；Codex 按改动范围执行本地 Maven、前端、Compose 或必要联调验证。
2. Codex 可以创建本地提交，但不会自行推送。用户推送阶段分支并告知 Codex PR 后，GitHub 自动运行功能验证。
3. 功能验证成功的非 Draft `feature/phase-<N>-*` PR，如未落后 `master`，自动在 sim 执行真实升级与干净安装验收。
4. 任一远端失败时，Codex 只报告当前 SHA、运行链接和诊断 Artifact；用户在本地修复并再次推送。
5. 阶段验收成功后，用户明确确认“合并并部署”，Codex 才 squash 合并、等待晋升校验并以实际 `master` SHA 触发部署。

## 安全与恢复

阶段验收会记录候选 SHA 的健康状态；squash 合并后，“阶段晋升关联”验证源码树一致并关联 `master` SHA。部署失败时，若无数据库迁移变化，部署脚本恢复上一健康镜像；否则保留脱敏诊断并停止。

`/opt/streamora/platform/compose/.env` 只由 sim Compose 读取，不能进入 Git、镜像、Artifact 或本机工具目录。旧的 `D:\aitool\loop-state` 不再被流程使用，保留为历史诊断，不能当作现行修复工作区。

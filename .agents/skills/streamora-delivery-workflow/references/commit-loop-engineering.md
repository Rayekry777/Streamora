# 本地提交规则

## 分组与验证

- 后端、用户端、管理端、契约、基础设施和文档按可独立回滚的边界分组；前端与后端业务改动不混在同一提交。
- IDEA 负责交互式调试和手动单模块测试；Codex 根据实际改动自动运行最小充分的 Maven、前端、Compose 或联调验证。
- `git diff --check` 和受影响验证通过后，Codex 才能在用户要求阶段提交时创建本地提交。

## 提交与推送

提交信息使用中文 Conventional Commit，并包含真实的功能明细、验证结果、未运行项和阶段状态。未运行项必须说明原因。

Codex 可以创建本地提交，但永远不因验证通过自动推送。推送、创建或更新 PR 均需要用户明确指令；用户推送后再通知 Codex 查询远端结果。

## 远端失败

远端失败只做诊断汇报。用户在 IDEA 或本地分支完成修复、重新验证和推送后，Codex 再查询新的 SHA。禁止自动修复 Agent、修复 PR、隐藏评论、自动合并和自动部署。
